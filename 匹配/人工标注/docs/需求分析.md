# 需求分析文档

> 人工标注 Web 应用 · `匹配/人工标注`

---

## 1. 项目背景

本项目旨在构建一个静态源码警告分类数据集，整体分三个阶段：

1. **版本追踪算法**（已完成）：跨版本追踪告警生命周期，若告警在后续版本消失则标注为 TP（已修复），持续存在则标注为 FP（误报）。
2. **LLM 自动分类**（已完成）：使用大语言模型对告警进行分析，产出四套结果（二/三分类 × 含/不含算法参考标签）。
3. **人工标注**（当前阶段）：对五套标签（1 算法 + 4 LLM）存在分歧的告警进行人工审核，产出最终 TP / FP 标签。

## 2. 数据规格

### 2.1 输入数据

| 文件 | 说明 |
|------|------|
| `input/origin_data/base_data.json` | 2510 条告警的完整基础信息，`label` 为算法标签 |
| `input/origin_data/results_with_unknown_with_label.json` | LLM 三分类 + 含算法参考标签结果 |
| `input/origin_data/results_with_unknown_without_label.json` | LLM 三分类 + 不含算法参考标签结果 |
| `input/origin_data/results_without_unknown_with_label.json` | LLM 二分类 + 含算法参考标签结果 |
| `input/origin_data/results_without_unknown_without_label.json` | LLM 二分类 + 不含算法参考标签结果 |

覆盖项目：curl、ffmpeg、git、libuv 等多个开源项目的多个版本（共 61 个版本目录）。

### 2.2 关键字段

| 字段 | 来源 | 说明 |
|------|------|------|
| `id` | base_data | 全局唯一整数 ID |
| `tool_name` | base_data | 产生告警的工具，如 `codeql` |
| `project_name_with_version` | base_data | 如 `ffmpeg-6.1.1` |
| `file_path` | base_data | 相对于项目根目录的源文件路径 |
| `line_number` | base_data | 告警所在行号 |
| `cwe` | base_data | CWE 编号列表，如 `["CWE-120"]` |
| `rule_id` | base_data | 告警规则编号 |
| `message` | base_data | 告警描述文本 |
| `severity` | base_data | 严重程度（部分工具提供） |
| `function_name` | base_data | 所在函数名 |
| `label` | base_data | 算法标签：`TP` / `FP` / `Unknown` |
| `llm_label` | LLM 结果 | LLM 标签：`TP` / `FP` / `Unknown` |
| `llm_label_reason` | LLM 结果 | LLM 判断理由 |
| `sliced_code` | base_data | 程序切片代码，警告行以注释标注 |

### 2.3 源码定位

给定告警的 `project_name_with_version` 和 `file_path`，源文件位于：

```
input/repository/{project_name_with_version}/{file_path}
```

## 3. 功能需求

### FR-1 数据合并

将 `base_data.json` 与四个 LLM 结果 JSON 按 `id` 字段合并为统一数据结构，每条记录包含：
- 基础信息字段（来自 base_data）
- 算法标签 `label`
- 四套 LLM 标签：`llm_label_wuwl`、`llm_label_wuol`、`llm_label_ouwl`、`llm_label_ouol`（及对应 reason）

### FR-2 不一致条目筛选

对每条告警，比较五个标签（算法 + 4 LLM）。**五个标签完全一致**的条目视为高置信度，跳过人工审核；**存在分歧**的条目加入待标注队列。

> `Unknown` 标签参与一致性判断——若五个结果均为同一值（含 Unknown）则视为一致。

### FR-3 告警列表与进度

- 分页或滚动展示待标注告警列表
- 页面顶部或侧边栏实时显示：已标注数 / 待标注总数

### FR-4 单条详情展示

每条告警展示以下信息（顺序如下）：

1. 基本信息：`id`、`tool_name`、`rule_id`、`cwe`、`severity`
2. 位置信息：`project_name_with_version`、`file_path`（可点击）、`line_number`、`function_name`
3. 告警描述：`message`
4. 五套标签对比：算法标签 + 4 个 LLM 标签（及理由）
5. 代码切片：`sliced_code`（置于最后）

### FR-5 源文件查看

点击 `file_path` 后，展示对应源文件的完整代码内容（读取自 `input/repository/`）。

### FR-6 警告行高亮

在源文件视图中，`line_number` 对应的行进行高亮显示，并自动滚动到该行。

### FR-7 人工标注

为当前告警打标签，可选值：
- `TP`（真实告警）
- `FP`（误报）
- `Unknown`（无法判断）

### FR-8 标注修改与删除

已标注的告警可重新打标签或删除标注，恢复为未标注状态。

### FR-9 标注持久化

标注结果保存至本地 JSON 文件（如 `annotations.json`），格式示例：

```json
{
  "1": { "label": "TP", "timestamp": "2026-03-17T10:00:00" },
  "2": { "label": "FP", "timestamp": "2026-03-17T10:01:00" }
}
```

### FR-10 导航快捷键

| 键 | 功能 |
|----|------|
| `A` | 上一条告警 |
| `D` | 下一条告警 |
| `N` | 跳至下一个未标注的告警 |

### FR-11 标注快捷键

| 键 | 功能 |
|----|------|
| `T` | 标注为 TP |
| `F` | 标注为 FP |
| `U` | 标注为 Unknown |
| `Delete` | 删除当前标注 |

### FR-12 进度统计

实时展示：
- 已标注数量
- 待标注总数
- 各标签（TP/FP/Unknown）计数

### FR-13 数据导出

提供导出接口，将完整数据（基础信息 + 五套标签 + 人工标注）导出为 JSON 文件，每条记录新增字段：
- `manual_annotation`：人工标注标签
- `annotation_timestamp`：标注时间
