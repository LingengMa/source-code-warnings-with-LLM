# 项目背景

整体项目背景需要构建静态源码警告数据集.

1. 通过匹配算法得出 TP / FP 的标签.
2. 大语言模型分析源码警告信息, 得出 TP / FP / Unknown 标签. 其中大模型分析分四类:结果带 / 不带 Unknown, 输入信息带 / 不带匹配算法所得标签, 输出结果如 input/origin_data 目录下的四个 json 文件.
3. 进行人工标注得出 TP / FP 标签.

目前我们阶段 1, 2 已经完成, 处于阶段 3.

> 文件说明
>
> base_data.json 包含完整的基础信息, 可结合 project_name_with_version 和 file_path 在 input/repository 中进行定位源文件. label是匹配算法得出的标签.



# 项目任务

1. 首先合并四种大模型匹配结果和匹配算法结果.

2. 然后筛选出匹配算法 + 四个大模型匹配结果共五个匹配结果, 没有完全一致的数据(五个数据完全一致则说明数据说服力强, 无需人工审)

3. 构建一个简单的 web 前后端项目, 用于进行人工数据标准. 要求功能:
   - 数据展示: 展示所有必要数据, 切片代码处于最后
   - 目前数据足以定位到源码警告所在源文件及所在行. 因此展示文件路径时可以进行点击查看该文件代码, 并且警告行高亮.
   - 快捷键: A/D 跳转到上/下一个源码警告, T/F/U进行人工标注. N 跳到下一个未人工标注的源码警告.
