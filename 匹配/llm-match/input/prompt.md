**任务背景：**
静态分析工具在扫描源码时可能产生误报（False Positive, FP）。当前需要对每一条静态分析告警进行判定，判断其是否为误报（FP），或是真实存在且应当修复的告警（True Positive, TP）。

**已有信息：**
对于每条告警，我们已提供以下信息作为输入：

* 静态分析工具名称（`tool_name`）
* 源码告警规则及描述（`rule_id`, `message`）
* 基于版本演化的算法匹配结果（`label`）
* 与告警相关的上下文源码片段（`sliced_code`）
* 其他必要的定位信息（如行号、函数名等）

**算法匹配结果说明（label 字段）：**
当前的 `label` 字段由自动匹配算法生成，其判定规则如下：

* 如果某条告警在后续版本中不再出现，则认为该告警已被修复，标记为 **TP**
* 如果某条告警在后续版本中仍然存在，则标记为 **FP**
* 最后一个版本的警告标记为 **Unknow**, 以从数据中剔除

该算法结果仅作为参考，可能存在误判。

**你的任务：**
请你综合以下信息：

* 静态分析工具及其告警规则语义
* 告警描述信息
* 算法给出的初始判断结果（`label`）
* 相关上下文源代码（`sliced_code`）

对该告警进行独立分析，判断其最终类型：

* **FP**：误报，不存在真实安全问题
* **TP**：真实且可修复的告警

并给出清晰、合理的判定理由。
